# 결정 기록

## 확정 (2026-10-28)

**D1. 정의**: 에이전트 네이티브 DB는 클라이언트가 틀릴 수 있다고 가정하는 DB다.
다른 업체들의 정의(생성 속도, 신선도, 맥락, 온보딩)는 이 전제를 돕는 하위 기능으로 포함된다. 정의는 반증 가능해야 한다. 클라이언트 오류를 DB 층에서 실제로 줄이는지 숫자로 보여준다.

**D2. 단독 서비스**: 특정 에이전트 제품의 부속이 아니다. 모든 에이전트가 쓰기 좋은 DB 계층이다.

**D3. 엔진이 아니라 Postgres 위 레이어**: 에이전트는 이미 Postgres를 쓴다(Neon에서 새로 생성되는 DB의 80%를 에이전트가 만든다). 도입 마찰을 없애고, Neon·Supabase·RDS·CedarDB 등 어떤 Postgres 호환 DB 위에도 얹는다. 엔진은 판단 계층이 가치를 증명한 뒤에 검토한다.

**D4. 확장이 아니라 프록시 + 사이드카**: 동기 경로(쓰기 게이트)는 pgwire 프록시, 비동기 경로(무효화·재평가)는 논리 복제를 구독하는 사이드카. Postgres 확장은 매니지드 환경에서 설치가 제한되고, 자체 엔진 호환 DB에서는 동작하지 않는다.

**D5. 모델 호출은 트랜잭션 밖**: 추론 지연과 장애가 DB 트랜잭션에 전파되지 않게 한다.

**D6. 판단 결과는 기록하고 재현 시 재추론하지 않는다**: 확률 모델의 비결정성 때문에 생기는 복제·재현 문제를 이렇게 푼다. 모델 버전은 고정한다.

**D7. 판단형 제약은 결정론적 제약 위에 얹는다**: 대체하지 않는다. 판단 대상(에이전트 입력)이 판단자를 조작할 수 있기 때문이다.

**D8. 모델 중립 인터페이스**: Jev는 첫 어댑터다. TypeSafe 단일 의존을 피하고, 판단 기록이 쌓이면 자체 판단 모델로 갈 경로를 열어둔다. Jev는 현재 고객별 파인튜닝을 제공하지 않는다.

**D9. 오픈 코어**: 코어는 Apache 2.0으로 공개하고 라이선스는 바꾸지 않는다. 돈은 추론 최적화, 고객별 보정·자체 모델, 운영 기능에서 받는다. 이유: 카테고리 정의는 오픈 프리미티브여야 퍼지고, 쓰기를 막는 레이어는 신뢰가 전부이며, 개념 자체는 어차피 숨겨서 지킬 수 없다.

**D10. v0.1 범위**: 프록시, 판단형 쓰기 게이트, 판단 기록, 섀도 모드. 섀도 모드에서 enforce로 넘어가는 비율을 PMF 지표로 본다.

**D11. 이름**: Stet. 교정할 때 "고친 걸 취소하고 원래대로 둬라(let it stand)"라는 표시다. 에이전트의 쓰기를 제안된 수정으로 보고 DB가 무엇을 남길지 정한다는 구조와 맞는다. 후보였던 Veto, Nunchi, Skeptic, Assay는 같은·인접 분야에 같은 이름이 있어 제외했다.

**D12. 구현 언어: Go** (2026-10-28 확정). 와이어 프로토콜은 프레임 단위로 원본 바이트를 중계하고, 검사할 메시지만 `pgx/v5/pgproto3`로 디코딩한다. SQL 분류는 `pg_query_go` v6(libpg_query, PG17 문법)로 Postgres 실제 파서를 쓴다. Go 모듈 경로 `github.com/stetdb/stet`은 GitHub 조직명을 확보하기 전까지 쓰는 가칭이다.

**D13. 섀도 모드 흐름: 상태는 동기, 판단은 비동기** (2026-10-28). 쓰기 전 값을 보려면 상태는 쓰기를 보내기 직전에 읽어야 한다. 모델 호출은 실행 결과가 나온 뒤 별도 고루틴에서 한다. 그래서 섀도 모드의 클라이언트는 상태 조립 시간(상한 500ms)만 기다리고, 모델 지연과 장애는 클라이언트에 닿지 않는다. enforce 모드에서는 판단을 기다려야 하므로 같은 단계를 동기로 묶는다.

**D14. 트랜잭션 안의 쓰기는 섀도 모드에서도 판단하지 않는다** (2026-10-28). 기록은 하되 verdict `unsupported`, reason `in_transaction`으로 남기고 모델을 부르지 않는다. 섀도 기록은 "enforce였다면 어땠을지"여야 하는데, enforce는 이 쓰기를 `ST002`로 거부하기 때문이다. pgx 배치처럼 한 Sync 안에 여러 문장을 보내는 것도 암묵적 트랜잭션이라 여기에 들어간다. 실험 에이전트는 autocommit 단일 문장으로 쓰게 해야 판단 데이터가 쌓인다.

**D15. `send_fields`는 필수** (2026-10-28). 기본값을 "모든 컬럼"으로 두면 설정을 빠뜨린 사용자의 데이터가 외부 모델 API로 나간다. 후보 SQL은 운영자가 직접 컬럼을 고르므로 후보 SQL 자체를 후보의 허용 목록으로 본다.

**D16. 모델 없는 기록 모드(`adapter: none`)** (2026-10-28). Jev 어댑터 전에도 섀도 모드를 돌려 쓰기 스트림과 상태를 쌓을 수 있다. 실험 1단계(쓰기 스트림 기록)는 이것으로 충분하다. 각 arm은 기록된 상태를 재생해 판단한다.

**D17. Jev는 TypeSafe API로 직접 부르고 버전과 응답 모델을 검사한다** (2026-10-28). `jev-X.Y.Z` 형식만 받고, 응답의 `model`이 다르면 답을 버린다. 키는 `TYPESAFE_API_KEY` 환경 변수로만 받는다. OpenRouter는 쓰지 않는다. 버전 고정을 직접 확인하기 어렵고, 경유 지점이 하나 늘기 때문이다.
